## فاز ۱۰ — برندینگ (لوگوی تو)

لوگو را **وکتوریزه** کردم، نه اینکه فقط PNG را تغییر اندازه بدهم. با تحلیل
تصویر هندسه دقیق استخراج شد:

| پارامتر | مقدار استخراج‌شده |
|---|---|
| شکل هر میله | مستطیل ۸۶×۳۰۱ |
| گوشه‌های گرد | **فقط دو گوشهٔ قطری** (بالا-راست و پایین-چپ)، شعاع ۴۳ = نصف عرض |
| زاویهٔ چرخش | ‎−۳۷.۵° |
| مرکز میله‌ها | (۲۰۸.۳۱، ۲۵۵.۸) و (۳۵۵.۴۲، ۲۵۵.۸) |
| مثلث | (۳۰،۳۲۲) → (۱۵۴،۳۲۲) → (۹۲،۳۸۴) |
| گرادیان میلهٔ چپ | ‎#FFFFFF → #BEFB00 |
| گرادیان میلهٔ راست | ‎#BEFB00 → #FFFFFF (آینه‌ای) |

**اعتبارسنجی:** SVG تولیدشده رستر شد و با تصویر اصلی مقایسه گردید:

- **IoU شکل: ۰.۹۹۵۶**
- **اختلاف میانگین پیکسل: ۱.۱۸ از ۲۵۵**

### نسخهٔ مخصوص اندازه‌های کوچک

در ۱۶ پیکسل مثلث به دو پیکسل خاکستری تبدیل می‌شد و حاشیه نیمی از فضا را هدر
می‌داد. یک master جداگانه ساخته شد که مثلث را حذف و میله‌ها را ۱.۲ برابر
می‌کند. اسکریپت `generate-branding.py` خودکار زیر ۳۲ پیکسل از این نسخه
استفاده می‌کند — همان کاری که هر آیکون حرفه‌ای ویندوز انجام می‌دهد.

پس:

| تم | accent متن | accent پرکننده |

## فاز ۴ و ۵ — رابط کاربری، تم و فونت

- نوار ابزار با Brand، Open، Reload، سوییچ سه‌حالته جهت، Zoom، تم، Settings
- Empty State با آیکون برند، راهنمای دوزبانه و میانبرها
- نوار وضعیت زنده: مسیر فایل، شمار بلوک‌های RTL، زمان رندر، حالت جهت، زوم
- Toast برای پیام‌ها
- تم روشن/تیره/خودکار کاملاً با CSS Custom Properties
- Vazirmatn با `local()` در اولویت، سپس نسخهٔ همراه — نسخهٔ Portable بدون
  نصب فونت هم درست است

### 🐛 باگ: فارسی داخل بلوک کد از هم می‌پاشید

فونت مونواسپیس معمولاً shaping عربی ندارد، پس حروف فارسی داخل کد جدا از هم
رندر می‌شدند. چون fallback فونت **در سطح glyph** انجام می‌شود، Vazirmatn به
انتهای صف `--font-code` اضافه شد: لاتین از Cascadia می‌آید و فارسی از
Vazirmatn.

## فاز ۷ — مهار سرریز

### تست خودکار: `tests/overflow.spec.ts` (۲۳ تست)

jsdom موتور چیدمان ندارد، پس این تست‌ها دو چیز را تضمین می‌کنند: هر سازهٔ
پرخطر داخل ظرف مهارکننده‌اش تولید می‌شود، و قواعد CSS مهارکننده هنوز در
شیوه‌نامه هستند. حذف `.table-wrap` یا `overflow-wrap: anywhere` اینجا شکست
می‌خورد، نه در پنجرهٔ کاربر.

### تست واقعی پیکسلی با Playwright

| عرض پنجره | `scrollWidth` / `clientWidth` | دکمهٔ کلیپ‌شده |
|---|---|---|
| ۱۲۰۰px | ۱۲۰۰ / ۱۲۰۰ ✅ | ۰ |
| ۴۳۰px | ۴۳۰ / ۴۳۰ ✅ | ۰ |
| ۳۶۰px | ۳۶۰ / ۳۶۰ ✅ | ۰ |

عناصر عریض‌تر از پنجره فقط `<pre>` و `<table>` هستند که **داخل اسکرولر خودشان**
قرار دارند — دقیقاً رفتار مورد نظر.

### 🐛 باگ: نوار ابزار در پنجرهٔ باریک کلیپ می‌شد

`overflow: hidden` جلوی پهن‌شدن پنجره را می‌گرفت (قید سند رعایت می‌شد) اما
دکمه‌های تم و تنظیمات ناپدید می‌شدند. یک کنترل نامرئی یعنی کنترل غیرقابل
استفاده. چهار breakpoint اضافه شد که به‌ترتیب اهمیت، کنترل‌های غیرضروری را
کنار می‌گذارد.
