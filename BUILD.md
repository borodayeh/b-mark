# Building B mark

## Prerequisites

| Tool | Version | Why |
|---|---|---|
| [Node.js](https://nodejs.org/) | 20 LTS or newer | frontend build and tests |
| [Rust](https://rustup.rs/) | 1.77+, **MSVC** toolchain | the desktop shell |
| Visual Studio Build Tools | 2019 or 2022, "Desktop development with C++" | the MSVC linker Rust needs |
| [Python](https://www.python.org/) | 3.10+ | only to regenerate icons from the SVG masters |
| WebView2 Runtime | any current version | to *run* the result; pre-installed on Windows 11 |

```powershell
rustup default stable-msvc
rustup target add x86_64-pc-windows-msvc
pip install cairosvg pillow
```

> **You can develop the whole frontend on Linux or macOS.** Everything in
> `src/` — the Markdown pipeline, the direction engine, themes, fonts and all
> 432 tests — runs anywhere Node runs. Only the final `.exe` needs Windows.

## Development

```bash
npm ci

npm run dev          # frontend only, in a browser at http://localhost:1420
npm run tauri:dev    # the real desktop window (Windows, needs Rust)

npm test             # 432 unit tests
npm run test:watch
npm run typecheck
```

`npm run dev` is genuinely useful: file opening falls back to `<input
type="file">` and drag & drop in the browser, so the Markdown and direction
engines can be exercised without a Rust toolchain at all.

## Production build

### Portable executable

```powershell
.\scripts\build-portable.ps1
```

The script checks the toolchain, installs dependencies, regenerates branding,
runs typecheck and tests, builds, then reports size and SHA-256.

Output:

```
release/
├─ B mark.exe
└─ SHA256SUMS.txt
```

### Per-user installer

```bash
sudo apt install nsis          # or: choco install nsis  on Windows
./scripts/build-installer.sh
```

Output: `release/B mark <version> setup.exe`

The script is a thin wrapper around `makensis` and
[`installer/b-mark.nsi`](installer/b-mark.nsi), which is **hand-written rather
than generated by the Tauri bundler**. Two reasons:

1. Every registry write the installer performs is visible in one reviewable
   file. For an app whose README makes claims about not touching HKLM, that
   matters more than the convenience of a generated script.
2. Tauri's NSIS bundler cannot currently be driven through `cargo-xwin` from
   Linux — the two disagree about CRT linkage and the build fails at link
   time. Calling `makensis` directly sidesteps that entirely and works
   identically on Windows and Linux.

What it produces:

| | |
|---|---|
| `RequestExecutionLevel user` | no UAC prompt, ever |
| `$LOCALAPPDATA\Programs\B mark` | install location |
| `HKCU` only | ProgID, `OpenWithProgids`, `RegisteredApplications`, Add/Remove Programs |
| `Target amd64-unicode` | native 64-bit installer, matching the app |
| English + Persian | asked **every** run; the remembered choice only preselects |

It checks for the WebView2 Runtime and warns if it is absent, but installs
anyway and **never downloads it** — see SECURITY.md.

Test it without installing anything on your own machine:

```bash
wine "release/B mark 0.1.2 setup.exe" /S     # silent install into a wine prefix
```

### ARM64

```powershell
rustup target add aarch64-pc-windows-msvc
.\scripts\build-portable.ps1 -Arch arm64
```

ARM64 is **experimental**. It builds and the CI produces an artifact, but we
have no ARM64 hardware to test on, so it is published with that caveat rather
than presented as a supported target.

### Cross-compiling from Linux or macOS

You do not need a Windows machine.

```bash
./scripts/build-windows-cross.sh
```

This uses [cargo-xwin](https://github.com/rust-cross/cargo-xwin), which
downloads Microsoft's own MSVC headers, import libraries and CRT from their
public CDN and links with `clang-cl` / `lld-link`. The output is a genuine
`x86_64-pc-windows-msvc` PE — not a MinGW build — so it behaves the same as
one produced on Windows.

Prerequisites beyond the normal set: `clang` and `lld`.

```bash
sudo apt install clang lld
rustup target add x86_64-pc-windows-msvc
cargo install cargo-xwin --locked
```

Two things the script sets that a naive `cargo build` does not, both of which
produce a *broken* binary if you forget them:

| Setting | Why |
|---|---|
| `--features custom-protocol` (via the crate's `default` feature) | Tauri gates the embedded frontend behind this. Without it the release binary looks for a dev server on `devUrl` and opens a **blank window**. |
| `-C target-feature=+crt-static` | Otherwise the exe imports `VCRUNTIME140.dll` and will not start on a machine without the Visual C++ Redistributable — which defeats the point of a portable build. |

**Memory.** Full LTO with `codegen-units = 1` needs roughly 4 GB. On a smaller
machine either add swap, or use the low-memory profile:

```bash
PROFILE=release-lowmem ./scripts/build-windows-cross.sh
```

`release-lowmem` inherits everything from `release` but disables LTO. The
official release is always built with the full `release` profile by CI.

### Verifying the result

```bash
pip install pefile
python scripts/verify-exe.py "release/B mark.exe"
```

Checks the things that produce a binary which *looks* fine but is not: a
console window in release, a missing icon or version resource, an unembedded
frontend, or a hidden CRT dependency.

### Signing

```powershell
.\scripts\build-portable.ps1 -Sign .\cert.pfx -SignPassword $env:CERT_PASS
```

Requires `signtool.exe` from the Windows SDK. Without `-Sign`, the script
prints an explicit warning that the binary is unsigned. See
[SECURITY.md](SECURITY.md).

## Branding assets

The vector masters in `assets/branding/` are the source of truth. Every PNG and
the multi-resolution `.ico` are generated from them:

```bash
python scripts/generate-branding.py
```

| Master | Used for |
|---|---|
| `bmark-icon.svg` | the app icon plate at every size, 16 px to 512 px |
| `bmark-mark.svg` | transparent mark for documentation |
| `bmark-mono.svg` | `currentColor` mark for in-app UI |

CI fails if the committed icons drift from the masters, so run the script
after editing any SVG.

## Troubleshooting

**`link.exe not found`** — install the Visual Studio Build Tools with the
"Desktop development with C++" workload, then restart the shell.

**`cargo` not found after installing rustup** — open a new terminal;
`%USERPROFILE%\.cargo\bin` is added to PATH only for new sessions.

**`python: command not found` in the build script** — no longer a problem: the
portable build uses the committed icons and only touches Python when you pass
`-RegenerateIcons` (which you need after editing an SVG, on a machine where
`pip install cairosvg pillow` works).

**Blank window on launch** — the WebView2 Runtime is missing or corrupt.
Install it from Microsoft's official page.

**Persian text renders as disconnected letters** — the bundled Vazirmatn
failed to load. Check the browser console in `npm run dev`; the `@font-face`
rules in `src/styles/fonts.css` must resolve to `assets/fonts/`.
